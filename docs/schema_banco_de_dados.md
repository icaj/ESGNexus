## Autoincremento — GENERATED BY DEFAULT AS IDENTITY

Todas as colunas `id` utilizam o recurso nativo do PostgreSQL 10+:

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY
```

Isso é equivalente ao antigo `SERIAL`, porém padronizado pelo SQL (ISO/IEC 9075) e com vantagens:

| Característica | `SERIAL` (legado) | `IDENTITY` (atual) |
|----------------|-------------------|--------------------|
| Padrão SQL | Não | Sim (SQL:2003) |
| Sequência interna | Exposta (`tablename_id_seq`) | Gerenciada internamente |
| Permite INSERT explícito | Sim | Sim (`BY DEFAULT`) |
| Suporte no SQLAlchemy 2.x | Via `autoincrement=True` | Via `Identity(always=False)` |

O modo `always=False` (`BY DEFAULT`) foi escolhido para permitir inserções com `id` explícito em migrações e testes.

### Migração automática

A função `_migrar_identity()` em `inicializacao_banco.py` converte instalações existentes (que usavam `SERIAL`) para `IDENTITY` de forma idempotente:

1. Detecta se a coluna já é `IDENTITY` → pula
2. Se ainda é `SERIAL` (default `nextval(...)`) → remove o default, adiciona `IDENTITY` com `START WITH <max_id + 1>`, descarta a sequência órfã
3. Ignora dialetos não-PostgreSQL (SQLite, etc.)

## Tabelas

### 1. `usuarios`

Autenticação e controle de acesso à plataforma. Sem FK para outras tabelas.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `nome` | `VARCHAR(120)` | NOT NULL | Nome completo do usuário |
| `email` | `VARCHAR(180)` | NOT NULL · UNIQUE · índice | Login e identificação |
| `senha_hash` | `VARCHAR(255)` | NOT NULL | Hash bcrypt da senha |
| `perfil` | `VARCHAR(30)` | NOT NULL · default `analista_esg` | Papel no sistema: `administrador`, `gerente_esg`, `analista_esg`, `operador_esg`, `cientista_dados` |
| `ativo` | `BOOLEAN` | NOT NULL · default `true` | Conta habilitada |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data de criação (UTC) |

**Índices:** `id` (PK), `email` (unique)

---

| `name` | `VARCHAR(220)` | NOT NULL · índice | Razão social |

| `environment_score` | `INTEGER` | NOT NULL | Score ambiental (0–1000) |
| `social_score` | `INTEGER` | NOT NULL | Score social (0–1000) |
| `governance_score` | `INTEGER` | NOT NULL | Score de governança (0–1000) |
| `cnpj` | `VARCHAR(20)` | NULL | CNPJ — chave de upsert |
| `email` | `VARCHAR(180)` | NULL | E-mail de contato |
| `telefone` | `VARCHAR(30)` | NULL | Telefone |
| `contato` | `VARCHAR(120)` | NULL | Nome do contato |
| `quantidade_funcionarios` | `INTEGER` | NULL | Número de funcionários |
| `endereco` | `VARCHAR(255)` | NULL | Endereço |
| `website` | `VARCHAR(255)` | NULL | Site |
| `descricao` | `TEXT` | NULL | Descrição livre |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data de criação (UTC) |

**Índices:** `id` (PK), `name`

### 3. `avaliacoes_esg`

Histórico de diagnósticos ESG. Cada chamada a `POST /classificar` ou `POST /avaliar/upload` gera um novo registro. Os campos `name` e `industry` são desnormalizados para consultas autônomas caso o fornecedor seja excluído.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `fornecedor_id` | `INTEGER` | FK · NULL · SET NULL · índice | Vínculo com `fornecedores.id` |
| `name` | `VARCHAR(220)` | NOT NULL · índice | Razão social (desnormalizado) |
| `industry` | `VARCHAR(100)` | NOT NULL | Setor (desnormalizado) |
| `environment_score` | `INTEGER` | NOT NULL | Score ambiental de entrada (0–1000) |
| `social_score` | `INTEGER` | NOT NULL | Score social de entrada (0–1000) |
| `governance_score` | `INTEGER` | NOT NULL | Score de governança de entrada (0–1000) |
| `total_score` | `INTEGER` | NOT NULL | Soma bruta dos três scores |
| `score_ponderado` | `FLOAT` | NOT NULL | Score ponderado pelos pesos do setor (0–1000) |
| `grade` | `VARCHAR(10)` | NOT NULL | Conceito (ex.: `A`, `B+`) |
| `level` | `VARCHAR(40)` | NOT NULL | Nível textual (ex.: `Avançado`) |
| `w_E` | `FLOAT` | NOT NULL | Peso ambiental aplicado |
| `w_S` | `FLOAT` | NOT NULL | Peso social aplicado |
| `w_G` | `FLOAT` | NOT NULL | Peso de governança aplicado |
| `fonte_pesos` | `VARCHAR(80)` | NOT NULL | Origem dos pesos: `setor` ou `global` |
| `risco` | `FLOAT` | NOT NULL | Índice de risco (0–100) |
| `impacto` | `FLOAT` | NOT NULL | Índice de impacto (0–100) |

| `confianca_rf_medium` | `FLOAT` | NOT NULL | Probabilidade RF classe `Medium` (%) |
| `maturidade_knn` | `VARCHAR(20)` | NOT NULL | Classificação pelo KNN |

| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data da avaliação (UTC) |

**Índices:** `id` (PK), `fornecedor_id`, `name`

---

### 4. `planos_acao`

Itens estruturados do plano de ação ESG por avaliação. Cada avaliação pode ter múltiplos itens (um por pilar que precisa de atenção). `fornecedor_id` é um atalho direto para consultas sem JOIN com a avaliação.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `avaliacao_id` | `INTEGER` | FK · NOT NULL · CASCADE · índice | Avaliação pai (`avaliacoes_esg.id`) |
| `fornecedor_id` | `INTEGER` | FK · NULL · SET NULL · índice | Atalho para `fornecedores.id` |
| `pilar` | `VARCHAR(5)` | NOT NULL | `E` (ambiental), `S` (social) ou `G` (governança) |
| `score` | `INTEGER` | NOT NULL | Score do pilar na avaliação (0–1000) |
| `importancia` | `FLOAT` | NOT NULL | Feature importance do Random Forest para o pilar |
| `acao` | `TEXT` | NOT NULL | Texto da ação recomendada |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data de criação (UTC) |

**Índices:** `id` (PK), `avaliacao_id`, `fornecedor_id`
**Cascade:** excluir uma `avaliacoes_esg` remove todos os seus `planos_acao` em cascata.

### 5. `experimentos_ml`

Rastreamento de execuções de treinamento ML. Sem FK para outras tabelas. Criado a cada execução de `treinar_modelo.py` ou `POST /treinar`.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `nome_execucao` | `VARCHAR(120)` | NOT NULL | Nome da run (ex.: `treino_20250615_143022`) |
| `knn_acuracia` | `FLOAT` | default `0` | Acurácia do KNN no conjunto de teste |
| `knn_f1_medium` | `FLOAT` | default `0` | F1-Score (classe Medium) do KNN |
| `knn_precision` | `FLOAT` | NULL | Precisão macro do KNN |
| `knn_recall` | `FLOAT` | NULL | Recall macro do KNN |
| `rf_acuracia` | `FLOAT` | default `0` | Acurácia do Random Forest no conjunto de teste |
| `rf_f1_medium` | `FLOAT` | default `0` | F1-Score (classe Medium) do RF |
| `rf_precision` | `FLOAT` | NULL | Precisão macro do RF |
| `rf_recall` | `FLOAT` | NULL | Recall macro do RF |
| `knn_params` | `TEXT` | NULL | Hiperparâmetros GridSearchCV do KNN (serializado) |
| `rf_params` | `TEXT` | NULL | Hiperparâmetros GridSearchCV do RF (serializado) |
| `mlflow_run_id` | `VARCHAR(120)` | NULL | ID da run no MLflow |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data e hora do treinamento (UTC) |

> **Nota de migração:** `knn_precision`, `knn_recall`, `rf_precision` e `rf_recall` foram adicionadas via `ALTER TABLE`. Registros anteriores têm `NULL` nessas colunas.

## Relacionamentos

| Tabela origem | Coluna | Tabela destino | Coluna | Cardinalidade | On Delete |
|---------------|--------|----------------|--------|---------------|-----------|
| `avaliacoes_esg` | `fornecedor_id` | `fornecedores` | `id` | N → 1 | SET NULL |
| `planos_acao` | `avaliacao_id` | `avaliacoes_esg` | `id` | N → 1 | CASCADE |
| `planos_acao` | `fornecedor_id` | `fornecedores` | `id` | N → 1 | SET NULL |

**Tabelas isoladas** (sem FK): `usuarios`, `experimentos_ml`

---

## Comportamento de deleção

| Cenário | Efeito |
|---------|--------|
| Excluir `fornecedores` | `avaliacoes_esg.fornecedor_id` → `NULL` · `planos_acao.fornecedor_id` → `NULL` |
| Excluir `avaliacoes_esg` | `planos_acao` vinculados são **removidos em cascata** |
| Excluir `usuarios` | Nenhum efeito em outras tabelas |
| Excluir `experimentos_ml` | Nenhum efeito em outras tabelas |

## Views

### `vw_fornecedores_classificacoes`

Lista cada fornecedor com sua **classificação ESG mais recente** e todos os itens do plano de ação correspondente.

- Retorna **uma linha por item de plano de ação** (ou uma linha sem plano quando o fornecedor ainda não foi avaliado)
- A avaliação mais recente é selecionada via `LATERAL JOIN` com `ORDER BY criado_em DESC LIMIT 1`
- Criada/atualizada automaticamente via `CREATE OR REPLACE VIEW` no startup da API e ao rodar `inicializar_banco.py`

**Colunas expostas:**

| Coluna | Origem | Descrição |
|--------|--------|-----------|
| `fornecedor_id` | `fornecedores.id` | ID do fornecedor |
| `razao_social` | `fornecedores.name` | Nome do fornecedor |
| `setor` | `fornecedores.industry` | Setor em inglês |
| `cnpj` | `fornecedores.cnpj` | CNPJ |
| `environment_score` | `fornecedores` | Score ambiental (0–1000) |
| `social_score` | `fornecedores` | Score social (0–1000) |
| `governance_score` | `fornecedores` | Score de governança (0–1000) |
| `fornecedor_criado_em` | `fornecedores.criado_em` | Data de cadastro do fornecedor |
| `avaliacao_id` | `avaliacoes_esg.id` | ID da última avaliação |
| `total_score` | `avaliacoes_esg` | Score total bruto |
| `score_ponderado` | `avaliacoes_esg` | Score ponderado (0–1000) |
| `pontuacao_esg` | calculado | Score na escala 0–100 (`score_ponderado / 10`) |
| `grade` | `avaliacoes_esg` | Conceito (ex.: `A`) |
| `level` | `avaliacoes_esg` | Nível textual |
| `risco` | `avaliacoes_esg` | Índice de risco (0–100) |
| `impacto` | `avaliacoes_esg` | Índice de impacto (0–100) |
| `quadrante` | `avaliacoes_esg` | Quadrante risco × impacto |
| `maturidade_rf` | `avaliacoes_esg` | Maturidade pelo Random Forest |
| `confianca_rf_high` | `avaliacoes_esg` | Confiança RF para `High` (%) |

| `w_e / w_s / w_g` | `avaliacoes_esg` | Pesos ESG aplicados |
| `fonte_pesos` | `avaliacoes_esg` | Origem dos pesos |
| `avaliacao_criado_em` | `avaliacoes_esg.criado_em` | Data da avaliação |

| `importancia` | `planos_acao` | Feature importance RF |
| `acao` | `planos_acao` | Texto da ação recomendada |

**Exemplos de uso:**

```sql
-- Todos os fornecedores com classificação e plano de ação
SELECT * FROM vw_fornecedores_classificacoes;

-- Apenas fornecedores de alto risco (score < 500)
SELECT DISTINCT fornecedor_id, razao_social, pontuacao_esg, risco
FROM vw_fornecedores_classificacoes
WHERE risco > 60
ORDER BY risco DESC;

-- Plano de ação completo de um fornecedor
SELECT pilar, pilar_score, importancia, acao
FROM vw_fornecedores_classificacoes
WHERE razao_social = 'Fornecedor Exemplo LTDA'
ORDER BY importancia DESC;

-- Resumo por setor
SELECT setor, COUNT(DISTINCT fornecedor_id) AS total,
       ROUND(AVG(pontuacao_esg)::numeric, 1)  AS score_medio
FROM vw_fornecedores_classificacoes
GROUP BY setor
ORDER BY score_medio DESC;
```

## Convenções

- Todas as PKs usam `INTEGER GENERATED BY DEFAULT AS IDENTITY` (PostgreSQL nativo, sem dependência de sequências externas).
- Todos os timestamps usam `TIMESTAMPTZ` (com fuso horário), armazenados em UTC.
- Scores ESG seguem a escala **0–1000** no banco; a conversão para 0–100 é feita na camada da API ou via coluna calculada `pontuacao_esg` na view.
- O campo `industry` armazena o valor em inglês no padrão do dataset Kaggle (ex.: `Technology`, `Healthcare`); a conversão PT → EN ocorre na rota `POST /classificar`.
